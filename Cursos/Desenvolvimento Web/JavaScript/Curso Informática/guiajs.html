JavaScript na prática

Programar é explicar a um computador, passo a passo, o que fazer. JavaScript é a linguagem que roda em todo navegador, e também a mais fácil de testar: basta abrir esta página.

Como usar este guia

Todo bloco escuro é um editor de verdade. Mude o código e clique em Executar para ver o resultado logo abaixo. Quebrar o código de propósito é permitido, e é assim que se aprende.

Dica: console.log(...) escreve algo na saída. É a sua lanterna para entender o que o programa está fazendo.

Um programa é uma sequência de instruções executadas de cima para baixo. Neste guia você vai aprender a guardar dados, tomar decisões, repetir tarefas e organizar o código em partes reutilizáveis.

Antes de começar: o que é programar?

Programar é escrever uma receita tão detalhada que até uma máquina, que não entende nada além do que você escreve, consegue seguir.

Uma receita diz: "pique a cebola, aqueça a panela, refogue por 3 minutos". O computador faz o mesmo, mas exige precisão total: se faltar um passo ou houver uma letra errada, ele não "adivinha", apenas avisa que não entendeu. Isso não é defeito seu, é só o jeito dele.

O caminho do computador

O computador segue a receita uma instrução por vez, de cima para baixo. Se entende a instrução, executa e passa para a próxima. Se não entende, mostra o erro e para. Quando as instruções acabam, o programa termina.

Como usar os blocos escuros

Clique dentro do bloco e digite à vontade. Executar (ou Ctrl+Enter) roda o código e mostra o resultado na janela preta. Restaurar devolve o exemplo original, então não existe risco de estragar nada. Errar faz parte: a mensagem de erro é uma dica, não uma bronca.

Ritmo: um capítulo por vez, sem pressa. Marque como concluído ao terminar e retome de onde parou quando quiser.

Pensamento algorítmico

Antes de escrever qualquer código, é preciso saber o que fazer. Um algoritmo é exatamente isso: uma sequência de passos, clara e sem ambiguidade, que resolve um problema.

Você já usa algoritmos o tempo todo: uma receita de bolo, o caminho para chegar a uma loja, o jeito de conferir o troco. Programar é traduzir um algoritmo para uma linguagem que o computador entende.

Três peças que servem para tudo

Sequência (um passo depois do outro), decisão (se isto, faça aquilo; senão, aquilo outro) e repetição (faça de novo, várias vezes). Com essas três peças se constrói qualquer programa. O fluxograma abaixo mostra uma decisão:

Do problema ao código

O segredo é quebrar o problema em passos pequenos e escrevê-los em português antes de programar. Depois, cada passo vira uma ou duas linhas de código.

Teste na cabeça: antes de rodar, simule o algoritmo com papel e caneta usando um exemplo. Se funcionar para valores comuns e para casos estranhos (lista com um só número, troco zero), ele provavelmente está certo.

Variáveis: caixas com nome

Um programa precisa lembrar de coisas: o nome do cliente, o saldo da conta, o preço de um produto. Uma variável é uma caixa etiquetada onde guardamos um valor.

O caminho do código

Cada linha do exemplo vira um passo. As duas primeiras criam caixas com nome e valor. A terceira (em amarelo) lê a caixa saldo, faz a conta e guarda o resultado na mesma caixa. A última mostra tudo na tela.

const ou let?

Use const por padrão. Só troque para let quando precisar mesmo mudar o valor. Assim, o computador avisa se você alterar algo sem querer. Evite var, a forma antiga, cheia de armadilhas.

Cuidado: tente executar cliente = "Seu João"; no exemplo acima. O erro é uma proteção, não um defeito.

Nomes não podem começar com número nem ter espaços. Por convenção, usa-se camelCase: saldoDaConta.

Tipos e operadores

Nem todo valor é igual: um número se soma, um texto se junta, um verdadeiro/falso se combina.

Os tipos de valor

Todo valor tem um tipo, e é o tipo que decide o que dá para fazer com ele. Estes são os cinco do exemplo: undefined é o que a linguagem usa quando ainda não há valor, e null é o vazio que você coloca de propósito.

O + junta textos, mas o - só sabe subtrair, então converte "5" em número. Essa conversão automática é fonte de bugs: prefira comparar com === (igual, sem conversão), nunca ==.

Comparando valores

Comparar é fazer uma pergunta ao JavaScript, e a resposta é sempre um boolean: true ou false. O === confere o valor e o tipo, então 5 (número) e "5" (texto) são diferentes. O == converte antes de comparar e acaba dizendo que são iguais, o mesmo tipo de surpresa do "5" + 3. Na última linha, as comparações se combinam com os operadores lógicos.

Lendo as três respostas da última linha: o && (E) só dá true quando os dois lados são verdadeiros, e 3 > 2 && 2 > 1 é verdadeiro. O || (OU) basta que um lado seja verdadeiro, mas 3 < 2 || false tem os dois lados falsos. O ! (NÃO) inverte o valor, então !true vira false. O resultado final é true false false.

Decisões com if

Programas ficam interessantes quando escolhem caminhos. Um if executa um bloco somente se a condição for verdadeira.

O caminho do if

Um if faz uma pergunta. Se a resposta for Sim, o programa executa o bloco. Se for Não, ele pula o bloco e segue direto. Nos dois casos, o programa continua depois do if.

if, else if e else

Com várias perguntas, o programa as faz na ordem e para na primeira resposta Sim. Com nota = 7.5, a primeira pergunta (nota >= 7) já dá Sim: só o caminho em amarelo roda, e as outras perguntas nem chegam a ser feitas. O else final é o caminho para quando todas as respostas são Não.

As condições vêm dos operadores do capítulo anterior. Alguns valores contam como "falso" numa condição: 0, "", null, undefined e NaN. Todo o resto é "verdadeiro".

Pense: o que aparece se a nota for exatamente 7? E se for 4.99? Teste os limites, é onde os bugs se escondem.

Escolhas: switch, ternário e valores padrão

Além do if, JavaScript tem atalhos para decisões comuns.

O caminho do switch

O switch olha o valor de dia e vai direto ao caso correspondente (em amarelo, o caso 3). Se nenhum caso combinar, vai para o default. O break faz o programa sair do switch e seguir adiante.

Com e sem break

Sem o break, o programa não sai do switch: ele continua executando o caso seguinte, mesmo que não combine com o valor. É a seta vermelha tracejada.

O caminho do ternário

O ternário é um if/else que devolve um valor: a condição vem antes do ?, o resultado para Sim logo depois, e o resultado para Não depois do :. Com idade = 67, o caminho em amarelo é o escolhido.

O caminho do ??

O ?? pergunta se o valor da esquerda é null ou undefined. Se for, usa o valor padrão da direita. Se não, usa o próprio valor. Como apelido é null, vale o padrão.

Atenção: sem o break, o switch "cai" para o caso seguinte. Teste tirar um deles.

Dica de legibilidade: se um ternário ficar difícil de ler, volte ao if. Código claro vale mais que código curto.

Repetições com laços

Computadores não cansam. Em vez de escrever a mesma coisa 100 vezes, escrevemos uma vez e mandamos repetir.

O caminho do for

O for reúne três partes entre parênteses. 1. Início (let i = 1) roda uma vez só. 2. Condição (i <= 10) é testada antes de cada volta. 3. Passo (i++) roda no fim de cada volta. A seta vermelha é a volta do laço: quando a condição fica falsa, o programa sai pelo "Não".

O caminho do while

O while tem só a condição. Preparar o começo (valor e meses) e mudar o valor a cada volta fica por sua conta, dentro do bloco. Se você esquecer essa mudança, a condição nunca fica falsa e a seta vermelha gira para sempre: esse é o laço infinito.

Laço infinito: se a condição nunca ficar falsa (por exemplo, esquecer a linha valor = valor * 1.01), a página trava. Se acontecer, feche e reabra a aba.

Use for quando sabe quantas voltas dará, e while quando depende de algo que vai acontecer.

Funções: receitas reutilizáveis

Uma função é um pedaço de código com nome. Você a define uma vez e a usa quantas vezes quiser, com entradas diferentes.

Parâmetros (preco, percentual) são as entradas; return devolve a saída e encerra a função. Variáveis criadas dentro dela existem só ali: esse é o escopo.

O caminho da função

Uma função é como uma máquina: as entradas (parâmetros) entram, o código trabalha lá dentro e o return entrega a saída. Em amarelo, o passo em que o resultado sai.

O escopo: uma caixa fechada

Tudo o que nasce dentro da função (preco, percentual, desconto) só existe lá dentro. De fora, desconto não é visível e dá erro. O único jeito de levar algo para fora é o return.

Regra de ouro: cada função deve fazer uma coisa só e ter um nome que diga qual é.

Arrays e objetos

Para guardar muitos valores usamos arrays (listas). Para agrupar características de uma coisa, objetos.

O caminho do código

As linhas do exemplo, até o segundo console.log, viram passos. Os passos em amarelo são os que alteram algo que já existia: a lista ganha um item e o objeto troca um dado.

O caminho do for...of

O laço pergunta se ainda há itens. Com Sim, pega o próximo, executa o bloco e volta a perguntar. Quando a lista acaba, o programa sai do laço.

map cria uma lista nova transformando cada item; filter mantém só os que passam num teste. Com listas, objetos, laços e funções você já organiza agendas, estoques e cadastros.

O caminho do filter

O filter faz o teste em cada item da lista. Quem passa entra na lista nova, quem não passa fica de fora. O map segue o mesmo caminho, só que sem a pergunta: todo item é transformado e entra na lista nova.

Treino: some os preços de uma lista de compras. Dica: precos.reduce((a, b) => a + b, 0).

Arrays em profundidade

Listas aparecem em todo programa. Estas ferramentas respondem perguntas comuns sem precisar escrever laços.

A esteira: filter, map e reduce

Os métodos de lista podem se encadear como uma esteira de fábrica: cada máquina recebe a lista, faz uma coisa e entrega o resultado para a próxima. Aqui, o filter deixa passar só os preços acima de 10 (o 8 fica de fora), o map aplica 10% de desconto em cada um e o reduce junta tudo em um único valor, o total. Em código: precos.filter(p => p > 10).map(p => p * 0.9).reduce((soma, p) => soma + p, 0).

Textos e números na prática

Quase todo programa manipula texto e faz contas. JavaScript já traz ferramentas prontas para isso.

Curiosidade: 0.1 + 0.2 não dá exatamente 0,3 porque o computador guarda números em binário. Isso acontece em quase todas as linguagens.

Matemática Básica

Descontos, aumentos, juros e parcelas: são contas que fazemos o tempo todo, e o computador as faz sem errar. Aqui você vê a matemática por trás delas.

Porcentagens

Uma porcentagem é uma fração de 100: 15% é o mesmo que 0,15. Para descontar 15%, multiplique por 0,85 (ou seja, 1 − 0,15). Para acrescentar 10%, multiplique por 1,10.

Juros compostos

Nos juros compostos, os juros de cada mês incidem sobre o valor já acumulado: é o famoso "juros sobre juros". A fórmula é capital × (1 + taxa) ^ meses.

Parcelas de um financiamento

O caminho da parcela

A função faz uma pergunta antes de calcular: se não há juros (taxaMensal === 0), basta dividir o valor pelos meses. Com juros, usa a fórmula do financiamento, o caminho em amarelo, que é o do exemplo com taxa de 2%. Qualquer que seja o caminho, a função devolve a parcela. Depois, o total pago é a parcela vezes o número de meses, e os juros são o total menos o valor original.

Cuidado com os arredondamentos: faça as contas com todas as casas decimais e arredonde só na hora de mostrar o resultado. Se preferir, trabalhe em centavos (números inteiros) para evitar surpresas como o 0.1 + 0.2.
Pense: compare a parcela com 12 e com 24 meses. A parcela cai, mas o total de juros pagos aumenta. Esse é o preço de "parcelar mais".

Datas e horas

Idade, prazos, vencimentos, aniversários: lidar com datas é parte do dia a dia, e JavaScript tem o objeto Date para isso.

Por que dividir por MS_POR_DIA?

O Date guarda cada data como um número gigante: os milissegundos que passaram desde 1970. Por isso, subtrair duas datas dá uma diferença em milissegundos, e não em dias. Para chegar em dias, divide-se pelo tamanho de um dia, o MS_POR_DIA (1000 ms × 60 s × 60 min × 24 h = 86 400 000). Quase sempre sobra uma fração, como 4,3 dias, e o Math.ceil arredonda para cima. Os números do diagrama são só um exemplo.

Treino: calcule quantos dias faltam para o seu próximo aniversário.

Erros e depuração

Todo programador passa boa parte do tempo corrigindo erros. A diferença está em saber lê-los e investigá-los com calma.

O caminho do try / catch / finally

O try tenta executar o bloco. Se algo der erro, o programa não quebra: ele pula direto para o catch, que recebe o erro. Se não der erro, o catch é ignorado. Nos dois casos, o finally roda no final.

O caminho do throw

Você também pode criar o seu próprio erro com throw. Em dividir(10, 0), a pergunta b === 0 dá Sim: o throw interrompe a função e o programa pula para o catch, que mostra a mensagem (caminho em amarelo). Com um b diferente de zero, a função segue normal e devolve a divisão.

Como caçar um bug

Leia a mensagem inteira, ache a linha citada, e use console.log para espiar os valores antes do ponto onde algo dá errado. Pergunte sempre: "o que eu achava que a variável valia, e o que ela vale de verdade?".

Objetos com comportamento

Um objeto não guarda só dados: pode ter funções próprias, chamadas de métodos. Uma classe é a planta para fabricar muitos objetos parecidos.

Da planta aos objetos

A classe é a planta: define quais dados (titular, saldo) e quais métodos (sacar, temSaldo) cada objeto terá. Poupanca herda tudo de Conta com o extends e ainda ganha o render. Cada new fabrica um objeto novo a partir da planta, com os próprios dados. O objeto p (em amarelo) usa os métodos que vieram da classe.

Pense: se um banco tivesse milhares de contas, preferiria copiar o objeto milhares de vezes ou usar uma classe? É para isso que elas existem.

Esperando sem travar

Carregar um arquivo, esperar um clique ou aguardar um servidor leva tempo. O JavaScript não fica parado: ele agenda a tarefa e segue em frente, como quem põe a água para ferver e vai picar a cebola.

A linha do tempo do setTimeout

O setTimeout não segura o programa: ele agenda a tarefa e libera as linhas seguintes. Por isso a ordem é 1, 2 e só depois 3. Leia o diagrama de cima para baixo, como o tempo passando: à esquerda, o programa; à direita, o temporizador contando em segundo plano. A seta tracejada é o aviso de que o tempo acabou.

Promises e async/await

Uma Promise é uma promessa de um valor futuro. Com async/await, escrevemos código que espera, mas lê como uma receita passo a passo.

Noções de HTML e CSS

Toda página da web é feita de três linguagens: o HTML diz o que está na página, o CSS diz como ela aparece e o JavaScript diz o que ela faz. Antes de mexer na página com JavaScript, vale conhecer as duas primeiras.

HTML: a estrutura

O HTML é feito de tags, escritas entre < >. A maioria tem uma abertura e um fechamento, e o que fica entre elas é o conteúdo. Neste capítulo, os blocos escuros são editáveis e o quadro branco mostra o resultado na hora.

As tags se encaixam como caixas dentro de caixas. Repare que os <li> estão dentro do <ul>: essa hierarquia forma a árvore que o DOM representa.

<ul>
 ├─ <li> Maçã
 └─ <li> Banana

Atributos: identidades e classes

Uma tag pode ter atributos, que a descrevem melhor. Dois são os mais importantes: id (nome único de um elemento) e class (nome de um grupo, que vários elementos podem compartilhar).

CSS: a aparência

O CSS escolhe elementos por um seletor e define como eles ficam: h1 escolhe pela tag, .destaque pela classe e #aviso pelo id. São os mesmos seletores que o querySelector usa no próximo capítulo.

Experimente: troque gold por lightblue, mude o tamanho da fonte ou dê a classe destaque ao último parágrafo.

A página web por dentro: o DOM

Todo site é feito de HTML, que descreve a estrutura (títulos, parágrafos, listas, botões). Ao abrir a página, o navegador monta uma árvore de elementos chamada DOM, e o JavaScript pode ler e alterar essa árvore: o que muda na árvore muda na tela.

Como ler os blocos deste capítulo: o bloco cinza é o HTML da página (fixo), o bloco escuro é o JavaScript (você edita), e o quadro branco mostra a página de verdade. Ao clicar em Executar, o código mexe na página.

A árvore da página

O navegador transforma o HTML em uma árvore: o document é a raiz e cada elemento é um nó. O querySelector("#titulo") percorre a árvore e devolve o nó do h1 (em amarelo). Com esse nó na mão, você altera o texto, o estilo ou a classe.

As três ideias

1. Encontrar: document.querySelector("#titulo") procura um elemento (# para o id, . para a class, nada para a tag, como "p"). 2. Alterar: textContent, style e classList. 3. Criar: createElement e append.

Criar e encaixar um nó

O createElement("li") cria um nó solto, que ainda não está na página. Só quando o lista.append(li) o encaixa como filho do ul ele aparece. Depois das três voltas do laço, a lista tem quatro filhos: o Farinha original e os três novos (em amarelo).

Experimente: troque "#titulo" por um nome que não existe. O elemento vira null e aparece um erro: a causa mais comum de bugs no DOM.

Eventos: a página reage a você

Um evento é algo que acontece na página: um clique, uma tecla, um campo preenchido. Dizemos ao navegador: "quando isso acontecer, rode esta função".

Neste exemplo, nada acontece até o clique: o código só registra a função com addEventListener("click", ...). Altere os números na página e clique em Dividir.

O caminho do evento

Um evento tem duas fases. Primeiro o programa registra a função e a página fica esperando. Só quando o clique acontece o navegador chama a função: ela lê os campos (sempre como texto), converte com Number(), confere se há pelo menos uma pessoa e mostra o aviso ou o resultado. Em amarelo, o clique e o caminho seguido com os valores iniciais (120 e 4).

Relógio e cronômetro

Até agora o código rodou uma vez e terminou. Com setInterval, ele repete uma tarefa de tempos em tempos, e é assim que se fazem relógios, cronômetros e contagens regressivas.

Um cronômetro com pausa

Repare que o cronômetro não conta os disparos do setInterval, porque eles não são exatos. Ele compara o horário real com Date.now(), que é confiável. O clearInterval para a repetição.

Os estados do cronômetro

O cronômetro tem três situações: parado, rodando e pausado. Cada botão leva de uma para outra, e os if (timer) return servem para ignorar cliques que não fazem sentido, como Iniciar quando já está rodando ou Pausar quando não há nada rodando.

Como o tempo é somado

Como o setInterval não é exato, a tela não soma disparos. Ao pausar, o programa guarda em decorrido o que já passou. Para mostrar, soma esse valor com o trecho atual, Date.now() - inicio, que só existe enquanto o timer está ativo.

Animação suave: um relógio de ponteiro

Para movimentos fluidos, usamos requestAnimationFrame: em vez de um intervalo fixo, pedimos ao navegador "chame esta função no próximo quadro de desenho". Ele cuida do ritmo (normalmente 60 vezes por segundo).

Experimente: no relógio digital, troque 1000 por 200 e veja o que muda. Depois, acrescente o ponteiro dos minutos no relógio de ponteiro.

Guardando dados no navegador

Sem isso, tudo some quando a página fecha. O localStorage guarda textos no navegador, e o JSON é o formato que transforma listas e objetos em texto (e de volta).

Lista de tarefas que não se perde

Adicione algumas tarefas e clique em Executar de novo: a página recarrega e a lista continua lá. Clique em uma tarefa para removê-la.

O caminho da lista

Toda vez que a página abre, o programa tenta ler o que ficou guardado: se houver uma lista válida, usa essa lista; se estiver vazio ou der erro, começa com uma lista vazia. A cada tarefa adicionada ou removida, o salvar() grava a lista como texto no navegador e o mostrar() atualiza a tela. O localStorage (em amarelo) fica fora da página, por isso continua lá quando você fecha e abre de novo: a seta tracejada mostra a lista sendo lida de volta.

Limites: o localStorage fica só neste navegador e neste computador, e guarda apenas texto. Se o navegador bloquear o armazenamento, o exemplo continua funcionando, mas sem guardar.

Buscando dados na Internet

Muitos serviços oferecem seus dados por uma API: um endereço que responde com informações (cotações, clima, notícias), geralmente em JSON. A função fetch faz o pedido.

O caminho do fetch

Um pedido pode falhar em pontos diferentes. Sem Internet, o próprio fetch falha e cai direto no catch (seta pontilhada). Se o servidor responde, mas com erro, resp.ok é falso e o throw leva ao catch. Só quando tudo dá certo o programa converte o JSON e mostra a cotação (caminho em amarelo).

Importante: este exemplo precisa de Internet e de que o guia esteja aberto direto no navegador (alguns visualizadores bloqueiam acesso à rede). O serviço gratuito também pode mudar ou sair do ar. Por isso o try/catch: toda busca na rede pode falhar, e o programa deve avisar com educação em vez de quebrar.

Desenhando com canvas

O elemento canvas é uma tela em branco onde o JavaScript desenha formas, textos e gráficos. Aqui, um gráfico de gastos do mês.

As coordenadas do canvas

No canvas, o ponto (0, 0) fica no canto de cima à esquerda. O x cresce para a direita, como esperado, mas o y cresce para baixo, ao contrário do plano cartesiano da escola. O fillRect(x, y, largura, altura) desenha a partir do canto de cima à esquerda, e a largura e a altura também crescem para a direita e para baixo. É por isso que, no gráfico, o chão das barras está em y = 150 e cada barra começa em 150 - altura: quanto maior a barra, menor o y do topo.

Experimente: mude os valores, troque a cor em fillStyle ou acrescente um novo gasto (aumente a largura do canvas se precisar).

Validando textos com regex

Uma expressão regular descreve um padrão de texto. É útil para conferir se um CEP, e-mail ou telefone foi digitado direito.

Peças básicas: \d = um dígito, \s = espaço, + = um ou mais, ? = opcional, ^ e $ = início e fim do texto. Regex parece um idioma à parte: aprenda aos poucos, conforme precisar.

O CEP como um trilho

O padrão /^\d{5}-?\d{3}$/ funciona como um trilho: o texto precisa percorrer todas as paradas, na ordem, do ^ ao $. O hífen é opcional, então existe um desvio que permite pular essa parada. O "88801-000" passa por todas e dá true. O "8880-000" tem só 4 dígitos antes do hífen, então trava na primeira parada e dá false.

Organizando o código

Código é lido muito mais vezes do que escrito, inclusive por você mesmo daqui a seis meses. Alguns hábitos facilitam a vida.

Antes e depois

As duas versões calculam exatamente a mesma coisa, mas só a da direita se explica sozinha. Cada nome vago vira um nome que responde à pergunta de quem lê: f vira totalComDesconto, a e b viram quantidade e precoUnitario, e o número solto 0.95 ganha um nome, DESCONTO_ATACADO.

Boas práticas: nomes que dizem o que a coisa é; funções pequenas, com um só objetivo; nada de "números mágicos" soltos (dê um nome a eles); comentários que explicam o porquê, não o óbvio.

Quando um programa cresce, dividimos o código em arquivos chamados módulos, que trocam funções com export e import. Isso exige arquivos separados, então não dá para praticar aqui, mas você vai encontrar no mundo real.

Glossário

Os termos que mais aparecem neste guia, em linguagem simples.

API
Endereço de um serviço que entrega dados a programas.
Array
Lista ordenada de valores, com posições a partir do 0.
Assíncrono
Tarefa que leva tempo e roda "em segundo plano", sem travar o resto.
Bug
Erro no programa que causa um comportamento inesperado.
Classe
Molde para criar vários objetos parecidos.
Condição
Pergunta de sim ou não que decide qual caminho seguir.
Constante
Variável cujo valor não muda (const).
DOM
A árvore de elementos da página que o JavaScript pode alterar.
Escopo
A região do código onde uma variável existe.
Evento
Algo que acontece na página, como um clique ou uma tecla.
Função
Trecho de código com nome, que pode ser usado várias vezes.
JSON
Formato de texto para representar listas e objetos.
Laço
Estrutura que repete um trecho de código.
localStorage
Pequeno armazenamento de textos dentro do navegador.
Método
Função que pertence a um objeto ou classe.
Objeto
Conjunto de dados e funções agrupados sob nomes.
Parâmetro
Entrada que uma função recebe.
Promise
Promessa de um valor que ficará pronto no futuro.
Regex
Padrão que descreve formatos de texto.
String
Um texto.
Variável
Caixa com nome onde se guarda um valor.
