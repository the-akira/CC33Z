Aprendendo C do zero, na prática

Um caminho passo a passo para quem nunca programou e quer entender de verdade o que acontece dentro do computador. Cada conceito vem com uma explicação simples, um exemplo que você pode rodar agora e um exercício para fixar.

Como usar este guia

Leia os capítulos na ordem: cada um usa o que foi aprendido no anterior. Em cada capítulo você vai encontrar sempre a mesma estrutura: uma ideia central explicada com analogias, programas completos para testar, um resumo e exercícios com dicas.

  4. Faça os exercícios antes de olhar as dicas. A dica só existe para desemperrar.

O que é um programa?

Um programa é uma lista de instruções que o computador executa uma por uma, na ordem. O computador é rapidíssimo, mas totalmente literal: ele não tem bom senso e não adivinha o que você quis dizer. Só faz exatamente o que está escrito.

Pense em uma receita de bolo. Se a receita disser "misture tudo" sem falar o que é "tudo", uma pessoa até se vira, mas o computador travaria. Uma receita clara, em ordem, sem ambiguidade e que termina em algum momento é o que chamamos de algoritmo.

Tudo é 0 e 1

Um computador é feito de bilhões de minúsculos interruptores que só têm dois estados: ligado ou desligado. Cada interruptor é um bit (do inglês binary digit), que vale 0 ou 1. Um grupo de 8 bits forma um byte.

Com 1 bit temos 2 combinações. Com 2 bits, 4. Com 8 bits, 2 × 2 × 2 × 2 × 2 × 2 × 2 × 2 = 256 combinações, ou seja, um byte pode guardar valores de 0 a 255. Cada posição vale o dobro da anterior, da direita para a esquerda:

Como um byte é pouco, medimos dados em múltiplos: 1 KB = 1.024 bytes, 1 MB = 1.024 KB, 1 GB = 1.024 MB. Uma música de 4 MB tem mais de 4 milhões de bytes. Programadores também usam o sistema hexadecimal (base 16) como abreviação de binário: o byte 01000001 vira 0x41.

Da ideia ao programa: o compilador

A CPU só entende instruções em código de máquina, sequências de 0 e 1 que ninguém quer escrever à mão. Por isso criamos linguagens mais próximas do nosso jeito de pensar, como o C. Mas o processador não entende C, então precisamos de um tradutor: o compilador.

Existem dois tipos de erro que você vai encontrar:

  • Erros de compilação: o compilador não consegue traduzir (faltou um ponto e vírgula, um nome está errado). O .exe nem chega a ser criado, e o compilador diz onde está o problema.
  • Erros de lógica: o programa compila e roda, mas faz a coisa errada (calculou uma média errada, por exemplo). Esses são os mais traiçoeiros, porque ninguém avisa.

Por que aprender C?

O C foi criado por Dennis Ritchie nos laboratórios Bell, no começo da década de 1970, e continua em uso mais de cinquenta anos depois. Há bons motivos:

  • É rápido e enxuto. Programas em C usam pouca memória e rodam muito depressa.
  • Mostra como o computador funciona. Em C você lida diretamente com memória, tipos e endereços. Quem aprende C entende melhor qualquer outra linguagem.
  • Aparece em todo lugar. O núcleo do Linux, partes dos sistemas operacionais, motores de jogos, o interpretador do Python e o firmware de microcontroladores (como os de Arduino) têm muito C ou C++ por baixo.
  • Abre portas. C++, C#, Java e JavaScript herdaram muita coisa da sintaxe do C.

Resumo do capítulo

  • Um algoritmo é uma sequência de passos claros, em ordem e finita; um programa é um algoritmo escrito para o computador.
  • CPU executa, RAM guarda o que está em uso (e esquece ao desligar), disco guarda para sempre.
  • Um bit vale 0 ou 1; 8 bits formam um byte, que guarda valores de 0 a 255.
  • Cada byte da memória tem um endereço; variáveis são nomes para esses lugares.
  • O compilador traduz o código-fonte em C para um executável que a CPU entende.

Exercícios

Algoritmo do dia a dia

Escreva, em passos numerados, um algoritmo para escovar os dentes ou para trocar a lâmpada de um abajur. Depois peça a um colega para "executar" seu algoritmo ao pé da letra e veja onde ele trava.

Ver dica

Não deixe nada implícito. "Pegue a escova" é um passo; "abra a gaveta" pode ser outro. Onde o colega travou é onde faltou um passo.

Lendo bytes

Sem usar o laboratório, calcule o valor decimal de 00001111 e de 10000000. Depois confira no laboratório.

Ver resposta

00001111 = 8 + 4 + 2 + 1 = 15. 10000000 = 128.

Quantas combinações?

Quantos valores diferentes cabem em 1 byte? E em 2 bytes (16 bits)?

Ver resposta

1 byte: 2⁸ = 256. 2 bytes: 2¹⁶ = 65.536. Cada bit a mais dobra o número de combinações.

Onde fica?

Para cada item, diga se está na RAM ou no armazenamento: (a) suas fotos do celular; (b) o jogo que está aberto agora; (c) um trabalho escolar salvo ontem; (d) o texto que você está digitando e ainda não salvou.

Ver resposta

(a) armazenamento; (b) RAM (o jogo foi copiado para lá ao abrir); (c) armazenamento; (d) RAM.

O que é uma IDE?

IDE significa Ambiente de Desenvolvimento Integrado. É um programa que reúne, em um só lugar, o editor onde você escreve o código, o compilador que o traduz e, geralmente, um depurador que ajuda a achar erros. Existem várias IDEs para C, todas fazendo essencialmente a mesma coisa por baixo: chamar um compilador (na grande maioria das vezes, o GCC ou algo compatível com ele) para transformar seu código em um programa executável.

Algumas opções gratuitas e populares para C, caso sua turma ainda não tenha uma definida: Dev-C++ e Code::Blocks (leves, boas para começar no Windows), CLion (mais completa, gratuita para uso educacional), Visual Studio Community (no Windows) e o VS Code com uma extensão de C/C++ (multiplataforma, mas exige configurar um compilador à parte). Também dá para escrever em qualquer editor de texto simples e compilar pelo terminal, sem IDE nenhuma — mostramos como no final deste capítulo. Siga as instruções específicas de instalação da ferramenta escolhida pela sua turma; os conceitos e passos gerais deste guia valem para qualquer uma delas.

Instalação em resumo

Os detalhes mudam de ferramenta para ferramenta, mas o caminho costuma ser parecido:

  1. Baixe o instalador na página oficial da ferramenta escolhida. Baixe apenas de fontes confiáveis.
  2. Execute o instalador. Se o sistema pedir permissão, confirme.
  3. Escolha o idioma, se disponível (muitas têm Português Brasileiro), e avance nas telas com as opções padrão.
  4. Ao abrir pela primeira vez, o programa pode pedir tema e fonte. Escolha o que for mais confortável para os olhos.

A maioria dessas IDEs já traz o compilador embutido ou o instala junto, então normalmente você não precisa instalar mais nada à parte.

Criando e salvando o primeiro arquivo

  1. Crie uma pasta curta para seus programas, por exemplo C:\programacao no Windows (ou ~/programacao no Linux/macOS). Evite espaços e acentos no caminho.
  2. No seu editor, vá em Arquivo > Novo > Arquivo Fonte (ou similar) ou pressione Ctrl+N.
  3. Pressione Ctrl+S para salvar. Na janela, escolha sua pasta e, no tipo de arquivo, selecione algo como C source files (*.c).
  4. Dê um nome sem espaços nem acentos, como ola.c.

Confira sempre a extensão! Se o arquivo for salvo como .cpp, seu compilador vai tratá-lo como C++, que é outra linguagem, com regras um pouco diferentes. Nosso guia é de C, então o arquivo deve terminar em .c.

  1. Comece pelo primeiro erro da lista. Um único erro costuma provocar vários outros em cascata.

A bifurcação

No dia a dia decidimos o tempo todo: se estiver chovendo, levo guarda-chuva; senão, deixo em casa. Em C escrevemos exatamente assim. A condição fica entre parênteses e o que fazer, entre chaves:

Se a condição for verdadeira, o bloco do if executa; se for falsa, executa o bloco do else (que é opcional). Depois disso o programa continua normalmente.

Vários caminhos: else if

Quando há mais de duas possibilidades, encadeamos condições com else if. O computador testa de cima para baixo e executa apenas o primeiro bloco cuja condição for verdadeira:

Use && (E) e || (OU) para condições mais ricas. Um exemplo clássico: descobrir se um ano é bissexto. A regra é: divisível por 4 e não por 100, ou divisível por 400.

Quando você compara uma mesma variável com vários valores fixos (um menu, um operador), o switch fica mais limpo que muitos else if. Cada case é uma possibilidade; o break encerra o caso, e o default cuida de qualquer outra coisa.

Sem o break, o programa "cai" para o próximo case e executa também o código dele. Às vezes isso é útil, mas quase sempre é um erro de distração.

Funções

Programas grandes não são escritos de uma vez: são montados com pecinhas pequenas, cada uma com uma tarefa. As funções permitem dar nome a um pedaço de código e reutilizá-lo quantas vezes quiser.

Por que usar funções?

Uma função é como uma máquina de suco: você coloca as frutas (parâmetros), aperta o botão (chama a função) e recebe o suco (retorno). Quem usa não precisa saber como a máquina funciona por dentro.

  • Reaproveitamento: escreve uma vez, usa muitas.
  • Organização: o main fica curto e legível, como um sumário.
  • Facilidade de testar e corrigir: cada função faz uma coisa só.

Você já usa funções desde o primeiro capítulo: printf, scanf, sqrt e strlen são funções escritas por outras pessoas. Agora você vai escrever as suas.

Anatomia de uma função

  tipo do retorno   nome     parâmetros
        │             │           │

       int        quadrado(   int n   ) {
           return n * n;    ◄── devolve o resultado
       }

Se a função não devolve nada, o tipo de retorno é void. Se não recebe nada, os parênteses ficam vazios (ou com void). Veja várias funções pequenas em ação:

O protótipo (a linha com ; no topo) apresenta a função ao compilador antes de ela ser usada. Sem ele, o compilador lê o main de cima para baixo e não sabe o que é quadrado. Se você definir as funções antes do main, os protótipos ficam dispensáveis.

Dê nomes de verbo às funções (calcularMedia, mostrarMenu) e faça cada uma cuidar de uma única tarefa. Se você precisa usar "e" para descrever o que ela faz, talvez sejam duas funções.

Cada função tem a sua "bancada"

As variáveis criadas dentro de uma função são locais: só existem enquanto ela roda e ninguém de fora as enxerga. Quando você passa um valor como parâmetro, a função recebe uma cópia. Modificar a cópia não altera a variável original:

Variáveis globais, declaradas fora de qualquer função, podem ser usadas por todas. Parece prático, mas dificulta achar erros, porque qualquer função pode mudar o valor. Prefira variáveis locais e parâmetros.

Um programa com menu, laço e funções: o main mostra o fluxo geral, e cada operação bancária fica em uma função. As funções que alteram o saldo devolvem o novo saldo, e o main guarda o resultado.

Diferente dos números simples, vetores não são copiados ao serem passados: a função trabalha no vetor original, e mudanças feitas lá dentro aparecem lá fora. No próximo capítulo você entenderá por quê.

Recursão: a função que chama a si mesma

Uma função pode chamar ela mesma para resolver um problema menor. O exemplo clássico é o fatorial: n! = n × (n−1)!, e 1! = 1. Toda função recursiva precisa de um caso base (a hora de parar), senão chama a si mesma para sempre.

Cada chamada fica "esperando" a próxima terminar, empilhadas como pratos. Quando o caso base é atingido, a pilha vai se desfazendo e as multiplicações acontecem:

fatorial(5) = 5 * fatorial(4)
                    = 4 * fatorial(3)
                          = 3 * fatorial(2)
                                = 2 * fatorial(1)
                                      = 1        ◄── caso base
  volta:  2*1 = 2  →  3*2 = 6  →  4*6 = 24  →  5*24 = 120

O tipo int tem limite: fatorial(13) já passa de 6 bilhões e provoca overflow (lembra do capítulo 4?). O resultado sai errado, sem aviso.

Resumo do capítulo

  • Função = tipo nome(parâmetros) { ... return valor; }.
  • void indica que a função não devolve nada.
  • Parâmetros de números são cópias: alterá-los não muda a variável original.
  • Variáveis locais só existem dentro da função.
  • Protótipos avisam ao compilador que a função existe; ou defina-as antes do main.
  • Recursão exige um caso base.

Toda variável mora em um endereço

Lembra da rua com casas numeradas do capítulo 1? Cada variável ocupa uma ou mais "casas" da RAM, e cada casa tem um endereço. O operador & revela onde a variável mora. Para mostrar um endereço, usamos %p:

Imagine que você quer que um amigo pegue um livro na sua estante. Você pode entregar uma cópia do livro, ou entregar um papel com a localização dele. O papel é o ponteiro: não é o livro, mas diz onde encontrá-lo. Com o papel, seu amigo pode até anotar algo no livro original.

Uso 3: pedir memória quando o programa já está rodando

Até agora, o tamanho de todo vetor era decidido antes de rodar. E se você só souber quantas notas terá depois que o usuário responder? Com malloc o programa pede memória à RAM no momento certo e recebe o endereço do bloco. Depois de usar, devolve com free.

  • Não use memória depois do free. O endereço continua no ponteiro, mas o espaço já não é seu.
  • Respeite os limites do bloco alocado, como nos vetores.

  • O nome de um vetor é o endereço do primeiro elemento.
  • malloc reserva memória em tempo de execução; free a devolve.

Uma ficha de cadastro

Uma struct é uma ficha com campos: nome, idade, nota. Cada campo pode ter um tipo diferente (o que os vetores não permitem). Você cria o molde da ficha uma vez e depois preenche quantas fichas quiser.

Passar uma struct por valor copia a ficha inteira. Se a função precisa alterar a original (ou se a struct é grande e queremos evitar a cópia), passamos um ponteiro para ela e usamos a seta -> para acessar os campos: j->pontos é o mesmo que (*j).pontos.

Método para caçar bugs

  1. Leia a mensagem inteira, começando pelo primeiro erro.
  2. Reproduza: descubra qual entrada faz o problema aparecer.
  3. Faça o teste de mesa no papel para o trecho suspeito.
  4. Imprima para investigar: coloque printf temporários para ver o valor das variáveis em cada ponto.
  5. Isole: comente partes do código até achar qual delas causa o problema.
  6. Explique o código em voz alta para alguém (ou para um objeto). Muitas vezes você acha o erro enquanto explica.

A maioria das IDEs (e também o GDB, usado por quem compila pelo terminal) tem um depurador, que executa o programa linha por linha e mostra o valor das variáveis. O caminho para ativá-lo muda de ambiente para ambiente, geralmente nas opções do compilador ou do projeto. Peça ao professor uma demonstração no ambiente que sua turma está usando: é como fazer o teste de mesa automaticamente.

Glossário

Os termos que apareceram ao longo do guia, em ordem alfabética, com explicações curtas.

Algoritmo
Sequência finita e ordenada de passos claros que resolve um problema.
ASCII
Tabela que associa um número a cada caractere básico (A = 65, a = 97, espaço = 32).
Bit
Menor unidade de informação do computador: vale 0 ou 1.
Buffer
Área de memória que guarda temporariamente dados, como o que foi digitado no teclado antes de o programa ler.
Byte
Grupo de 8 bits; guarda valores de 0 a 255.
Compilador
Programa que traduz o código-fonte em código de máquina (executável).
Constante
Valor que não muda durante a execução (const ou #define).
Depuração (debug)
Processo de encontrar e corrigir erros (bugs) em um programa.
Endereço
Número que identifica a posição de um byte na memória.
Escopo
A região do programa em que uma variável existe e pode ser usada.
Executável
Arquivo (.exe no Windows) que o computador consegue rodar diretamente.
Função
Bloco de código com nome, que recebe parâmetros e pode devolver um resultado.
Heap
Área da memória usada para alocação dinâmica com malloc.
IDE
Ambiente de desenvolvimento integrado: editor, compilador e depurador juntos (como Dev-C++, Code::Blocks, CLion ou VS Code com as extensões certas).
Índice
Número que indica a posição de um elemento em um vetor; começa em 0.
Laço (loop)
Estrutura que repete um bloco de código: for, while, do-while.
Overflow
Quando um valor ultrapassa o limite do tipo e "dá a volta".
Parâmetro
Variável de uma função que recebe o valor enviado por quem a chamou.
Ponteiro
Variável que guarda o endereço de outra variável.
Protótipo
Declaração de uma função (sem o corpo) que a apresenta ao compilador.
RAM
Memória de trabalho do computador: rápida e volátil.
Recursão
Técnica em que uma função chama a si mesma.
Retorno
O valor que uma função devolve com return.
String
Texto: vetor de char terminado em '\0'.
Struct
Tipo composto que agrupa campos de tipos diferentes sob um nome.
Teste de mesa
Simulação no papel da execução de um código, acompanhando os valores das variáveis.
Tipo de dado
Define o que uma variável pode guardar e quantos bytes ocupa: int, float, char...
Variável
Espaço nomeado da memória que guarda um valor que pode mudar.
Vetor (array)
Conjunto de elementos do mesmo tipo guardados em sequência na memória.
